# V2: Course Workspaces

Product/design evolution plan for `basics-web`. Builds on the v1 design pass
(commit `3f269f1`: forest-green tokens, Bricolage Grotesque headings, bezeled
buttons, Phosphor icons, PageHeader, de-call-ified lesson room).

## Vision

Each course becomes a **workspace** (like a Codex project / Littlebird space).
**Voice tutor sessions are the PRIMARY modality** — going live must always be
one direct action (a prominent "Start live lesson" / "Go live" button), never
gated behind a chat. The text chat is a SUPPORTING channel: a place to talk
through context, ask questions between sessions, and drop in documents so the
agent can tailor lessons to them (deepens later). Escalating a chat to live is
an option, not the main path. The app shell gets a rich sidebar (search,
collapsible course sections, recents), a real Home page, and a custom
account/settings surface built on Clerk hooks (no Clerk-rendered components).

## Locked design decisions

- Theme: forest/pine green tokens, light-only for now (dark tokens dormant).
  Heading font: Bricolage Grotesque (`font-heading tracking-tight`). Icons:
  Phosphor (`@phosphor-icons/react`, `/dist/ssr` in server components),
  Regular weight default, `weight="fill"` for active/selected states.
- Buttons: bezeled style already in `apps/web/src/components/ui/button.tsx`.
  No decorative icons on CTA buttons (user explicitly dislikes them).
  IMPORTANT: use `bg-linear-to-*` (Tailwind v4 names), never `bg-gradient-to-*`
  — the legacy names break tailwind-merge and silently strip `bg-*` colors.
- Chat UI: follow https://www.assistant-ui.com/examples/perplexity EXACTLY in
  structure (user request): hero wordmark + tall rounded-3xl multi-line
  composer (`rows={2}`, `min-h-20`), functional mode dropdown, attachment
  chips above input, four-state primary action (Cancel / StopDictation /
  Send / Dictate), sticky follow-up composer footer with fade gradient.
  Use `@assistant-ui/react` primitives (`npx assistant-ui add thread` as a
  starting point), restyled with our forest tokens (NOT their cream palette).
  Mode dropdown options: "Chat" / "Live lesson" (instead of Search/Research).
- Sidebar: collapsible course sections per the shadcn example saved in
  `newsidebar.txt` (Collapsible + SidebarMenuSub). NOTE: repo uses shadcn
  "base-nova" style on @base-ui/react — use `render={<Link/>}` not `asChild`.
- Search: command palette (cmdk-style) opened via sidebar search field and
  Cmd+K; searches courses, lessons, chats.
- Settings: dialog (tabs), launched from a Codex-style account menu in the
  sidebar footer (email header, Profile, Settings, Log out). Use Clerk hooks
  (`useUser`, `useClerk().signOut()`, `user.update()`), never Clerk UI
  components.
- Uploads: S3 via SST v3 at repo root (user has AWS CLI configured). RDS is
  DEFERRED — local Postgres (docker-compose) stays for dev; RDS is a
  deployment concern for later.
- Enrollment: real `Enrollment` model + migration, self-serve enroll.
- Chat <-> live: a chat can ESCALATE to live — "Go live" continues the same
  session in the lesson room.
- Modality hierarchy: live voice is primary. Every workspace surface keeps a
  direct "go live" action (workspace header action, per-lesson Start lesson
  buttons, Continue strip resume). Chat is for context/questions/documents
  and must never be a required step before a live session.

## What the codebase already provides (verified)

- **Text chat backend exists**: `POST /api/sessions/[sessionId]/turns`
  (apps/web/src/app/api/sessions/[sessionId]/turns/route.ts) streams tutor
  turns via `@basics/tutor` (AI SDK + @ai-sdk/openai runtime in
  packages/tutor). Persists learner utterances + tutor events to the
  session event log. See `apps/web/src/lib/tutor-service.ts` and
  `apps/web/src/lib/session-store.ts` (`appendEvents`, `getOwnedSession`,
  `getOrCreateLessonSession`).
- **Schema is ready** (packages/db/prisma/schema.prisma): `Workspace`,
  `Session` (courseId/lessonId both nullable — a chat thread is a Session
  with courseId set, lessonId null; `topic` can be the thread title),
  `SessionEvent` + projections, `ContextSource` (sourceType/label/content
  Json/retention/consent — designed for uploaded material; currently only
  used for `screen_snapshot` via /api/sessions/[id]/context), `Summary`,
  `MasteryObservation`. There is NO Enrollment model yet.
- **Live room is per-session**: lesson room connects via
  `TokenSource.endpoint(/api/sessions/${id}/connection-details)`, so any
  session can in principle go live. RISK: verify `apps/agent` (LiveKit agent,
  apps/agent/src/main.ts) handles sessions with `lessonId: null` before
  building escalation around it.
- Existing UI inventory: shadcn base-nova components in
  `apps/web/src/components/ui/`, LiveKit agents-ui components, ai-elements
  (message/conversation), `PageHeader` in
  `apps/web/src/components/page-header.tsx`.
- Monorepo: pnpm + turbo. Web app: `apps/web` (Next 16, React 19, Tailwind
  v4 CSS-first in `apps/web/src/app/globals.css`). Dev runs through doppler.
  Lint/typecheck: `pnpm --filter web lint` / `typecheck`.

## Target information architecture

- `/` — Home (replaces the current redirect to /courses)
- `/courses` — catalog (browse + enroll)
- `/courses/[courseId]` — workspace home: header row (title + "Go live"
  top-right), composer, then Lessons / Chats / Materials tabs
- `/courses/[courseId]/chats/[sessionId]` — chat thread (sticky composer,
  "Go live" escalation)
- `/courses/[courseId]?tab=materials` (or /materials deep link) — Materials
  tab of the workspace home
- `/courses/[courseId]/lessons/[lessonId]/learn` — live lesson room
  (unchanged route)

## Phase 1 — Data model: Enrollment + chat threads

1. Add `Enrollment` to packages/db/prisma/schema.prisma:
   `id`, `learnerId`, `courseId`, `status` (e.g. "active"), `enrolledAt`,
   `@@unique([learnerId, courseId])`, relations + indexes. Follow existing
   conventions (string ids, snake_case `@map`, `@@map("enrollments")`).
   Run migration via `pnpm db:migrate` (packages/db scripts; read
   migration-best-practices rule first).
2. Server action / helper to enroll + unenroll (idempotent upsert).
3. `POST /api/courses/[courseId]/chats` — creates a chat Session
   (courseId set, lessonId null, topic null initially) for the learner,
   mirroring `getOrCreateLessonSession` conventions but always-new.
4. Auto-title threads: after first learner turn, set `session.topic` from
   the first message (truncate ~60 chars; optionally LLM-generated later).
5. Query helpers for sidebar/home: recent chat sessions per course
   (lessonId null), enrolled courses for learner.

## Phase 2 — Sidebar v2, Cmd+K palette, account menu + settings dialog

1. Sidebar (`apps/web/src/components/app-sidebar.tsx`):
   - Header: brand row + collapse trigger (already done in v1), then a
     search field that opens the command palette (shows ⌘K hint).
   - "Home" item, then "Courses" group: one Collapsible section per
     ENROLLED course (pattern from newsidebar.txt, adapted to base-nova
     `render` prop) containing: Overview (workspace home link), 3-4 recent
     chats ("Show more" expands), Materials link. Active states use
     Phosphor fill weights.
   - Empty state: if not enrolled in anything, show a "Browse courses" CTA.
2. Command palette: add a command component (shadcn base-nova registry if
   available, else build on Dialog + cmdk), global Cmd+K listener in the
   (app) layout. Sources: enrolled courses, their lessons, recent chats.
3. Account menu (`apps/web/src/components/nav-user.tsx`): Codex-style
   dropdown — email header (muted), Profile, Settings, separator, Log out.
   Data via `useUser()`; sign out via `useClerk().signOut()`.
4. Settings dialog component: tabs Profile (displayName edit via
   `user.update({ firstName/lastName or unsafeMetadata })` + Learner row
   sync) and Account (email read-only, password change link/flow later).
   Keep it honest: only ship controls that actually work.

## Phase 3 — Workspace home + assistant-ui chat

1. Add `@assistant-ui/react`. Generate starter thread components
   (`npx assistant-ui add thread`) into `apps/web/src/components/chat/`,
   then restyle to forest tokens following the Perplexity example structure
   (composer shell, dropdowns, four-state action, sticky footer, user
   bubble `rounded-3xl rounded-tr-md`, assistant avatar).
2. Custom runtime adapter bridging assistant-ui to the existing turns
   endpoint: send -> POST /api/sessions/[id]/turns, parse the event stream
   (see turnStreamResponse in apps/web/src/lib/tutor-service.ts for the
   wire format), map transcript events to assistant messages. History
   hydrates from session events (transcript projections).
3. Workspace home `/courses/[courseId]` — Littlebird-style hierarchy
   (reference: Littlebird project page screenshot — header row with project
   name left + "New meeting" button top-right, composer below, tabs +
   search + content list under that). Top to bottom:
   - COMPACT HEADER ROW: course title (Bricolage, left, optionally with a
     small course glyph) and a PRIMARY bezeled "Go live" button pinned
     top-right — exactly where Littlebird puts "New meeting". Go live
     targets the next/first lesson's learn route (smarter "next lesson"
     selection once progress exists). This button is the page's primary
     action; voice stays the headline modality.
   - COMPOSER directly below the header: full-width Perplexity-style
     rounded box, placeholder "Ask about this course or drop in
     material...", attachment "+" on the left, mode dropdown + dictate/send
     cluster on the right (four-state action). Submitting creates a chat
     via POST /api/courses/[courseId]/chats and routes to the thread page
     with the first message sent. Prominent, but visually subordinate to
     the header row — a good part, not the main part.
   - TABS below the composer (Littlebird's "Chats and notes /
     Instructions" slot): "Lessons" (DEFAULT tab, voice-first) / "Chats" /
     "Materials", with a search/filter input row beneath the tab bar.
   - TAB CONTENT list: Lessons tab = lessons grouped by module with direct
     "Start lesson" buttons (adapt current course detail content), plus a
     "Continue" resume row pinned at the top when a recent session exists.
     Chats tab = recent chat threads. Materials tab = uploads (Phase 4;
     show an empty-state teaser until then). Friendly dashed-border empty
     states like Littlebird's "This project is empty".
   - Note: tabs replace the earlier idea of separate /materials-only
     navigation emphasis; the sidebar Materials link just deep-links to
     the Materials tab.
4. Thread page `/courses/[courseId]/chats/[sessionId]`: message list +
   sticky composer; header with thread title, "Go live" button.
5. Escalation: FIRST verify apps/agent handles lessonId-null sessions
   (read apps/agent/src/main.ts + instructions.ts). Then "Go live" routes
   to a live room view for the same session (reuse LessonRoom with a
   nullable lesson — it already types `lesson: Lesson | null`).

## Phase 4 — Materials + S3 via SST

1. `sst init` (SST v3) at repo root: S3 bucket component, dev mode via
   `sst dev`. Only the bucket for now — no RDS, no web deployment.
2. API route for presigned upload URLs (auth via learner context); accept
   pdf/txt/md/images, size cap.
3. On upload completion: create `ContextSource` row — sourceType "upload",
   label = filename, content = { s3Key, mimeType, size, extractedText? }.
   Text extraction best-effort (e.g. `unpdf` for PDFs) so the tutor can
   use material content in turn context (see buildTurnContext).
4. Materials tab on the workspace home: upload (drag/drop + button), list
   with type icons, delete. Composer attachment button feeds the same
   pipeline and attaches the ContextSource ids to the session
   (`session.contextSourceIds` field exists).

## Phase 5 — Home page

1. `/` becomes Home (move redirect logic; keep (app) shell):
   - "Jump back in": latest active/recent sessions with resume links —
     live lessons listed first/most prominent (voice-first), chats after.
   - Enrolled courses with simple progress (sessions per lesson as proxy
     until real progress exists).
   - "Start something new": unenrolled catalog rows with Enroll buttons
     (server action from Phase 1).
2. `/courses` stays the full catalog with enroll/unenroll states.
3. Sidebar "Home" item links here; update brand link.

## Verification per phase

- `pnpm --filter web typecheck && pnpm --filter web lint` after each phase.
- Phase 1: migration applies cleanly; enroll/unenroll round-trips.
- Phase 3: chat round-trip against the real tutor runtime (dev runs with
  doppler); escalation produces a working live room on the same session.
- Phase 4: upload -> ContextSource row -> material text reaches the tutor
  turn context.
- Visual checks in the dev server (usually already running — check the
  terminals folder before starting a new one).

## Known risks / open items

- apps/agent behavior for lessonId-null sessions (Phase 3 blocker — check
  first).
- assistant-ui runtime adapter vs custom turn stream format — budget time
  to study `turnStreamResponse`'s wire format before wiring.
- Clerk profile updates: confirm which fields the app actually reads
  (Learner.displayName) and sync direction.
- SST adds an infra dependency; keep it scoped to the bucket so dev
  remains doppler + docker-compose.
